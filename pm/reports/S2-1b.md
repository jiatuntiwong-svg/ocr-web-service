# S2-1b — Harness robustness (login + upload flake fixes)

**Status:** 👀 review
**Owner:** qa-tester
**Date:** 2026-07-12
**Scope:** `scripts/ocr-e2e/harness.mjs` only (no runner / assertion changes, no deploy)

## Context

The last benchmark run against prod (deploy `c900a2d2`) recorded 86.1% overall
vs. the locked baseline 88.9% — but 11/12 real content cases still passed
(91.7%, matching baseline). The gap was harness scaffold flakes, not OCR
regression. Two failure signatures reproduced ≥3× across recent runs:

### Flake 1 — login submit detached-element retry → 30 s timeout

```
error: page.click: Timeout 30000ms exceeded.
  waiting for locator('button[type="submit"]')
  - element was detached from the DOM, retrying
```

**Root cause (hypothesis):** The login form re-renders (client state update or
conditional `<form>` swap) between locator resolution and click. Playwright's
built-in auto-retry keeps re-resolving to a still-detaching node, burning the
full 30 s budget without ever landing the click.

### Flake 2 — `setInputFiles` on `input[type="file"]` → 30 s timeout

```
error: locator.setInputFiles: Timeout 30000ms exceeded.
  waiting for locator('input[type="file"]').first()
```

**Root cause (hypothesis):** The v2 workspace stage machine renders the file
input only when the upload stage is active. On cold Workers (wrangler init +
hydration), the input can attach past the default 30 s locator timeout. The
prior harness relied on the implicit wait inside `setInputFiles`, so a slow
attach surfaces as a "no locator" timeout rather than a bounded wait.

## Fix summary (diff)

`scripts/ocr-e2e/harness.mjs`:

### Login (step 1)

- `page.goto(/login)` now followed by `waitForLoadState("networkidle")` so the
  initial hydration + any re-render settles before we resolve the button.
- Submit click wrapped in a **2-attempt loop** with re-locate:
  - Each attempt: `.waitFor({ state: "attached", timeout: 15_000 })` then
    `.click({ timeout: 10_000 })` (short timeout so we don't burn 30 s on a
    detach loop before retrying).
  - On failure matching `/detached|Timeout|not visible|not enabled/i`, log
    `[HARNESS_RETRY]` to stderr, wait 500 ms, and re-locate + retry.
  - Non-matching errors propagate immediately (don't mask real bugs).
- **Fallback:** if both click attempts fail, submit the `<form>` directly via
  `page.evaluate(form => form.requestSubmit() || form.submit())`. This
  sidesteps the locator-vs-render race entirely — the DOM node reference
  used is resolved *at eval time* inside the page, not from a Playwright
  locator handle.
- `waitForURL` timeout bumped 15 s → 30 s to cover retry + fallback.

### Upload (step 3)

- Explicit `.waitFor({ state: "attached", timeout: 45_000 })` before
  `setInputFiles` — v2 keeps the input visually hidden but DOM-reachable, so
  `"attached"` (not `"visible"`) is the correct state. 45 s budget absorbs the
  cold-Worker tail.
- Fixed `waitForTimeout(2500)` after `setInputFiles` replaced with a
  **signal-based race**: whichever of the following appears first within 10 s
  ends the wait — `Next: Fields` button, `Next: Run` button, or the template
  name row. If none appear in 10 s we log `[HARNESS_RETRY]` and continue
  (the downstream `templateLocator.waitFor(..., 15_000)` still gates progress).

### Instrumentation

- All retry / fallback paths write `[HARNESS_RETRY]` prefixed lines to
  `stderr` only. Happy-path runs stay silent; future benchmark logs can be
  grep-filtered to count flake incidence over time.
