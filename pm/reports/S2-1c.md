## Why

Full-suite single-shot benchmark against prod (`https://ocr-web-service.jiatuntiwong.workers.dev/`) reliably aborts around case 4-5 with `net::ERR_ABORTED` — provider/edge rate limit somewhere in the chain. Batched runs (one category per invocation with 2-3 min cooldown between) proved on 2026-07-13 that 36/36 = 100% is achievable, but each batch writes its own `_summary-*.json` and there was no way to fuse them into a single baseline-shape snapshot for `--fail-under` gating and delta tracking.

## Deliverables

### 1. `scripts/ocr-regression/merge-summaries.mjs` (new)

Combines N `_summary-*.json` files into a single baseline-shape snapshot. Same schema as an individual summary (so `--fail-under` and delta on the next run keep working) plus provenance fields.

- Inputs via repeatable `--input <path>` or a single `--glob <pattern>` (only `*` wildcard in basename — no `**` recursion).
- Recomputes `scoring.overall` (pooled: `sum(passing runs) / sum(runs)`) and `scoring.perCategory` (arithmetic mean of case pass rates + meets-threshold ratio) from the merged case list.
- Deduplicates case ids across inputs: **latest `startedAt` wins**, shadowed entries emit a `[merge] duplicate case id` warning.
- Metadata reconciliation: first non-empty `suite`/`baseUrl` wins with a warning on mismatch; conflicting `config` paths are a hard error.
- Adds `synthetic: true`, `syntheticSources: [{ path, timestamp }, …]`, `syntheticNotes` (default explains the batching workaround; overridable via `--notes`).
- Fail-fast on: no inputs matched, missing file, malformed JSON, unknown flag, conflicting configs.

CLI:
```
node scripts/ocr-regression/merge-summaries.mjs --help
node scripts/ocr-regression/merge-summaries.mjs \
  --input pm/reports/OCR-2-runs/_summary-A.json \
  --input pm/reports/OCR-2-runs/_summary-B.json \
  --output pm/reports/OCR-2-runs/_baseline.json

# Or by glob:
node scripts/ocr-regression/merge-summaries.mjs \
  --glob 'pm/reports/OCR-2-runs/_summary-2026-07-13T16-*.json' \
  --output pm/reports/OCR-2-runs/_baseline.json
```

### 2. `--delay-ms` flag in `scripts/ocr-regression/run.mjs`

- New flag: `--delay-ms <N>` — sleeps N ms after each **passing** run before the next run.
- Applied at both inter-run (within a case) and inter-case boundaries.
- Skipped after the final run of the last case (no next), and skipped after failing runs (no point pacing a broken run).
- Default 0 keeps existing behavior byte-identical.
- Verbose log line: `[DELAY] sleeping ${N}ms before next run`.
- `--help` output updated.

Example:
```
node scripts/ocr-regression/run.mjs \
  --config scripts/ocr-regression/cases/benchmark.json \
  --category dense --runs 10 --delay-ms 4000
```
