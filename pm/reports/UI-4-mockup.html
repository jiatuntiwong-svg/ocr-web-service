UI-4 Mockup OCR Workspace Decluttering

Static HTML mockup สำหรับให้ PM + operator รีวิว ก่อนเปิดตั๋ว UI-4b (implementation). ไม่ใช่โค้ดจริง — ใช้ token สีเดียวกับ src/app/globals.css เพื่อให้ feel ใกล้แอปจริง

สรุปแนวคิด Concept summary

Mockup นี้เสนอการ reorganize หน้า OCR โดย ไม่ตัดฟีเจอร์ใดออก — แค่ย้ายเครื่องมือให้ตรงตามลำดับงาน. ให้อ่านทั้ง 3 state ด้านล่างเทียบกับหน้า OCR ปัจจุบันแล้วสังเกตว่า "แต่ละขั้นตอนเห็นเฉพาะเครื่องมือของมัน":

  • 1. จัดเรียงตามลำดับงาน — Stepper บนหัว: อัปโหลด → เลือกหน้า → ฟิลด์ → รัน → ผล → export. เครื่องมือของ stage อื่นถูกซ่อน/ย่อ (progressive disclosure).
  • 2. Progressive disclosure — Hint drawing, raw_text toggle, batch options อยู่ใน "ตัวเลือกขั้นสูง" ที่ต้องกดเปิด (หรือ hover ที่ chip ของ field แล้วจะเห็น mini-toolbar).
  • 3. Two-zone layout — ซ้ายคือ preview (ขยายพื้นที่), ขวาคือ แผงเดียว ที่ เปลี่ยนเนื้อหาตาม stage — แทนที่จะยัดทุก panel ซ้อนกันเหมือนตอนนี้.
  • 4. Result row เดียว ไม่ซ้อน — corrections badge / confidence / source / rules รวมในบรรทัดเดียวต่อ field, action หายากซ่อนใน overflow menu (⋯) — WRONG, ดูรายละเอียด, retry-เฉพาะ-field.
  • 5. คงทุกฟังก์ชัน — ไม่มีอะไรถูกลบ ทุก action ยังกดถึงได้, ยังคงภาษาไทย + English เหมือนเดิม.

หมายเหตุการ implement Implementation notes for UI-4b

รายการที่ implementer ควรอ่านก่อนเริ่มแตะโค้ด — บาง item ดูเหมือนย้ายกล่อง แต่จริงๆ ผูกกับ state / coordinate math ที่ซับซ้อน.

⚠️ Hint drawing overlay ไม่ trivial

OCR-6c เพิ่งแก้ coordinate drift บนหน้า landscape (iframe letterbox). ถ้าจะย้าย overlay ไปอยู่ใน "advanced expander" หรือให้เปิดจาก hover chip — ต้องระวังว่า overlay ผูกกับ preview element ตัวเดียวกันเสมอ ห้าม remount overlay ระหว่างสลับ stage (จะทำให้ hint pin หลุดตำแหน่ง). แนะนำ: overlay อยู่ใน DOM ตลอดเวลา แค่ toggle pointer-events / opacity.

🔀 Batch mode = top-level toggle, ไม่ใช่ stage

Mockup วาง Batch เป็น mode switch ที่ topbar (ไฟล์เดียว / หลายไฟล์). สลับ mode = เปลี่ยนโครง zone ทั้งหมด: preview ซ้ายกลายเป็น file list, right panel = template + fields summary + run-all. Stepper ต้องเปลี่ยนคำ (เลือกหน้า → เลือกไฟล์). Implementer ตัดสินใจว่าจะ share right-panel components หรือ fork.

⛔ Error states ทำอย่างไรใน stepper?

Mockup ไม่ได้แสดง error state. แนะนำ: (1) error ตอน upload = stepper 1 กลายเป็นสีแดง + right panel แสดง friendlyError (UI-3) + CTA "ลองใหม่", ไม่ auto-advance stage. (2) error ตอน run = ค้างที่ stage 4, right panel แสดง error + "Retry" (UI-2). (3) partial success (บาง field null) = ไปที่ stage 5 ปกติ, chip เหลืองว่ามีปัญหา.

🚦 Migration: default view จะเปลี่ยนทันทีหรือหลัง flag?

Operator เดิมชินกับ layout เก่า (panels ซ้อน). แนะนำ flag featureFlags.ocrWorkspaceV2 เริ่มปิดใน prod, PM/operator เปิดใน preview ก่อน validate; หลัง feedback รอบ 1 ค่อยเปิดใน prod. ห้ามลบ code เดิมทันที — ต้อง fallback ได้.

📐 State management ต้องเพิ่ม currentStage

OCRWorkspace.tsx ตอนนี้ไม่มี concept ของ stage — ทุก panel render พร้อมกัน. UI-4b จะต้องเพิ่ม currentStage: 'upload' | 'pages' | 'fields' | 'run' | 'results' ใน state, กำหนดกฎ auto-advance (upload success → pages, extract success → results) และให้ user คลิก stepper กระโดดถอยหลังได้ (แต่ไม่ควรกระโดดข้ามไปข้างหน้าถ้า stage ก่อนหน้าไม่ครบ).

💡 Rules badge ยังไม่มี backend

Mockup แสดง 💡 RULE · date-normalize เพื่อ preview OCR-Rulebase feature. Feature นี้ยัง ไม่ implemented (ดู docs/RULEBASE_LEARNING_LOOP_PLAN.md). Implementer UI-4b ไม่ต้อง ทำ badge นี้ให้ live — แค่เผื่อพื้นที่ใน result-row meta-row ไว้ให้ badge ในอนาคต.

🔤 ทุก string ผ่าน i18n

Mockup ใช้ string ไทยที่พบใน src/lib/i18n/locales/th.ts เป็นหลัก (extractCta, uploadHeadline, pagePicker.*, batch*). String ใหม่ที่ต้องเพิ่ม: stepper labels (6 stage), overflow menu items (แจ้งว่าผิด/ดูรายละเอียด/รันเฉพาะฟิลด์นี้ใหม่), "ตัวเลือกขั้นสูง". English labels ต้องคู่กันทั้งหมด — ห้าม hard-code.
